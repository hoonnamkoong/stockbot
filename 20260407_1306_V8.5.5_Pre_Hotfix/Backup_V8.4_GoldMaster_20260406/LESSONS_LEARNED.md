# ARCHITECTURE_V8.4: Attention Deep-Dive & Real-Trade

## 1. 개요 (Overview)
본 시스템은 대중의 관심(Attention)과 AI 분석(Deep-Dive)을 결합하여 실거래(Real-Trade)까지 자동 수행하는 3단계 정밀 깔때기 분석 엔진입니다.

## 2. 데이터 파이프라인 (Data Pipeline Flow)

### Phase 1: Buzz Filter (수합 및 1차 필터링)
- **대상**: 네이버 금융 거래상위(Top 30) 및 상승률 상위(Top 20) 종목 전수 조사 (실제 약 113개 티커).
- **필터**: 15:00 KST 기준, 당일 08:00 이후 생성된 게시글 수가 **120개 이상**인 종목만 통과.

### Phase 2: Bulk Ai Sentiment (AI 집단지성 분석)
- **입력**: 필터링된 종목별 추천 상위 5개 게시글 본체.
- **최적화**: AI에게 전달 시 본문 텍스트를 **200자** 내외로 슬라이싱하여 토큰 부하 방지.
- **처리**: `gemini-2.5-flash` 모델을 **단 1회 호출**하여 모든 종목의 감성 점수(-10 ~ 10)를 산출 (비용 및 속도 최적화).

### Phase 3: Selection & Execution (최종 선정 및 집행)
- **랭킹**: [ML 확률(기술지표) + AI 감성 점수(5배 가중치)] 합산 기준 상위 15개 종목 선정.
- **리포트**: 상위 5개 종목에 대해 '버즈 발생 원인(Trigger)' 및 '커뮤니티 인사이트'를 개별 분석하여 텔레그램 발송.
- **주문**: Vercel/KIS API를 통해 실거래 집행 및 예약 주문(Catch-up) 관리.

# LESSONS_LEARNED (V8.4 - 2026-04-06)

## 1. KIS API SYDB0050 오류 대응
- **현상**: 잔고 조회 시 첫 페이지 이후 데이터 로드 실패.
- **원인**: `tr_cont` 파라미터가 불분명하게 전달되거나 중복됨.
- **해결**: 모든 API 호출 시작 시 `tr_cont=""` (빈 문자열)로 명시적 초기화하여 첫 페이지 응답을 강제함.

## 2. Gemini API 429 & Prompt Overload 해결
- **현상**: 종목별 개별 AI 호출 시 쿼터 제한(429) 및 응답 지연 발생.
- **해결**: `analyze_bulk_sentiment`를 통해 Bulk 처리를 도입하고, 데이터가 잘리는 것을 방지하기 위해 본문 텍스트를 **200자 슬라이싱** 규칙 적용.

## 3. 파이프라인 단절 (Empty List) 이슈
- **현상**: 코드 수정 중 원본 수집 로직이 빈 리스트(`[]`)로 하드코딩되어 분석이 중단됨.
- **교훈**: 배포 전 '수원지(Source)' 데이터의 존재 여부를 반드시 체크하고, 주석이나 스켈레톤 코드가 라이브 환경에 나가지 않도록 `py_compile` 및 자가 검증 절차 강화.

## 4. 텔레그램 마크다운 파싱 에러
- **현상**: AI 응답에 포함된 HTML 태그(`<br>`, `<b>`)가 텔레그램 앱에서 깨지거나 날것으로 노출됨.
- **해결**: AI 프롬프트에 HTML 사용 금지 지침을 박고, 강조는 오직 마크다운(`**텍스트**`)만 사용하도록 고정.
