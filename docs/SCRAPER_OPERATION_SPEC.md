# 스크래퍼 & 텔레그램 동작 조건 명세

## 스크래퍼 동작 조건

1. **트리거**: 태스커(Tasker) 신호에 의해서만 시작 (`workflow_dispatch`)
2. **장 확인**: 오늘이 주식 거래일(장 개장일)인 경우에만 실행, 비거래일은 즉시 종료
3. **실행 작업**:
   - 스크래핑 데이터를 대시보드에 정리
   - 시뮬레이터에 데이터 제공 및 가상 거래 실시
   - 엑셀에 데이터 저장

## 텔레그램 동작 조건

1. **전제**: 스크래퍼가 정상 실행된 경우에만 발송
2. **시각 조건**: 매시 **정각**에 실행된 스크래퍼 데이터만 텔레그램으로 리포트 송부
   - 정각 기준: 스크래퍼 프로세스 시작 시각의 분(minute)이 0분(정각)일 때
   - 15분, 30분, 45분 등 중간 실행분은 발송하지 않음

## 현재 코드 대비 조건 위배 및 잠재 문제

### 문제 1 — `is_trading_day()` 9시 오탐 [조건 위배: 스크래퍼 조건 2]

**파일**: `src/pipeline/context.py:85`

**현상**: 매시 9:00 KST 실행 시 Naver Finance `span#time` 조회 결과가 이전 거래일 날짜를 반환.
장이 막 열린 직후(9:00~9:05)에는 네이버 증권 페이지가 아직 당일 날짜로 갱신되지 않아
`naver_date("2026.05.29") ≠ today_display("2026.06.01")` → 휴장일로 잘못 판단하고 종료.

**증거**: 9:00 실행(Run #2024) Run Scraper 단계 소요 시간 **2초** (정상 실행 80초).

**위배 조건**: 거래일임에도 파이프라인이 조기 종료됨 → 스크래핑·시뮬·엑셀 저장 미실행.

### 문제 2 — `should_notify()` minute 0~2 제한이 `workflow_dispatch`에도 적용 [조건 위배: 텔레그램 조건 1]

**파일**: `src/pipeline/context.py:107`  
**변경 커밋**: `5c99bac` (2026-05-06, "정각 알림 강화")

**현상**: `workflow_dispatch` 이벤트임에도 `start_minute`이 0~2가 아니면 `False` 반환.
문제 1로 인해 9:00 실행이 조기 종료되면, Tasker가 9:15·9:30에 재시도해도 모두 발송 차단.

**증거**: 9:15 실행(Run #2025) 80초 정상 실행 완료 → 그러나 텔레그램 미발송.

**위배 조건**: 스크래퍼가 정상 실행되었음에도(조건 1 충족) 텔레그램 미발송.

**참고**: 이전 코드(`ff56e30` 이전)는 `workflow_dispatch`를 항상 `True`로 처리했으나
`ff56e30`에서 예외 제거 후 현재까지 유지됨. 의도는 "정각에만 발송"이나
9:00 실행이 오탐으로 죽으면 9:15 재시도가 정상 실행되어도 발송 불가 상태가 됨.

### 문제 3 — GitHub Actions `schedule` 트리거 미동작 [잠재 문제]

**현상**: 마지막 `schedule` 이벤트 실행이 2026-05-29. 이후 오늘(2026-06-01)까지
`schedule` 트리거가 없고 모두 `workflow_dispatch`(Tasker)로만 실행됨.

**원인 추정**: GitHub는 60일 이상 저장소에 활동이 없으면 스케줄 워크플로우를 자동 비활성화.
또는 main 브랜치에 최근 data/** 외 경로 push가 없어 스케줄이 멈춘 상태일 수 있음.

**잠재 위험**: Tasker가 작동 안 하는 상황(폰 꺼짐, 앱 오류 등)에서 `schedule`도 없으면
당일 스크래퍼가 아예 동작하지 않음.

**확인 방법**: GitHub → Actions → Stock Scraper Schedule → "This workflow has a schedule trigger" 표시 여부 확인.

### 문제 4 — `start_minute` 기준 시점 불일치 [잠재 문제: 텔레그램 조건 2]

**파일**: `src/pipeline/context.py:24`

```python
self.start_minute: int = self.now_kst.minute
```

**현상**: `start_minute`은 `PipelineContext` 생성 시각 기준 = **스크래퍼 Python 프로세스 시작 시각**.
태스커가 9:00:00에 `workflow_dispatch`를 보내도, GitHub Actions 준비 단계(checkout, pip install, git fetch)에
약 40~50초 소요되어 스크래퍼 프로세스는 9:00:51에 시작됨.

현재는 minute=0이므로 문제없지만, GitHub Actions 대기 큐가 밀려 9:01:30 이후에 시작되면
`start_minute=1` 또는 `2`가 되어 아슬아슬한 경계에 걸림.

**권고**: `should_notify()` 허용 범위를 0~4분(또는 0~5분)으로 넓혀 여유를 두는 것이 안전.
