# Sim1 전일 스냅샷 저장 — d_sov·accel·d_hype 설계

2026-07-28

## 배경

Sim1 진입식의 설계안은 4항이다.

```
ignition = 1.0*z_posters + 1.0*z(d_sov) + 0.7*z(d_hype) + 0.5*z(likes_per_post)
```

그런데 `d_sov`·`d_hype`는 전일 값과의 차이라 이력이 있어야 만들 수 있고, 저장하는 코드가
없다. 그래서 현재 구현은 관측 가능한 3항(`z_posters + z_sov + z_likes`)만 합산한다
([sim1_psych.py](../../../src/strategy/simulators/sim1_psych.py)).

이력은 소급 생성할 수 없다. 저장을 시작한 날부터만 쌓인다.

## 실측 — 무엇을 저장해야 하는가

전일 기준값을 원값(sov)으로 둘지 z로 둘지가 첫 갈림길이었다. db-data 커밋 히스토리가
런별 스냅샷이므로 직접 측정했다(2026-07-28, 41개 런 × 24종목, 09:05~16:22).

| 기준 | 09:05 | 10:00 | 13:00 | 15:30 |
|---|---|---|---|---|
| sov 원값 편차 (종가 대비 중앙값) | 61.7% | 31.8% | 12.9% | 2.1% |
| **z_sov 편차** | 1.03z | **0.20z** | **0.09z** | 0.02z |
| posts 원값 편차 (대조군) | 77.2% | 57.7% | 17.9% | — |

`recent_posts_count`는 당일 누적이다. 따라서 원값은 오전에 구조적으로 작고, 전일 종가값과
그대로 빼면 d_sov가 시간대 노이즈가 된다. 횡단면 z는 누적 스케일을 상쇄하므로 이 편향이
사라진다. sov 순위상관은 09:26 이후 rho 0.95~0.99로 안정적이다.

**결정: 스냅샷은 z 스케일로만 저장한다.**

부수 관측: 09:05~09:15는 z조차 중앙 1.03z·90분위 2.46z로 요동한다. 개장 30분은 횡단면
자체가 아직 형성되지 않는다.

## 실측 — 유니버스 회전율

전일 이력이 없는 종목의 처리 방식이 몇 %에 영향을 주는지 측정했다(최근 4거래일, 각 날의
마지막 런 스냅샷 비교).

| 날짜 | 종목수 | 전일 유지 | 신규 유입 | 신규 비율 |
|---|---|---|---|---|
| 2026-07-24 | 26 | 16 | 10 | 38.5% |
| 2026-07-27 | 25 | 13 | 12 | 48.0% |
| 2026-07-28 | 24 | 13 | 11 | 45.8% |

**매일 후보의 38~48%가 신규 유입이다.** 결측 처리는 예외 처리가 아니라 절반의 정책이다.

## 범위 — 이번에 하지 않는 것

**진입식은 현행 3항을 그대로 둔다.** 이번 배포는 이력 축적·계산·로깅까지다.

이유: 4항을 지금 진입식에 넣으면 ignition 스케일이 달라져 임계값 2.5가 무의미해지는데,
재조정 근거가 될 진단 로그는 배포 다음 거래일이 첫 수확이다. 지금 넣으면 "이력 도입"과
"임계값 변경" 두 변화가 한 번에 섞여 원인을 분리할 수 없다. Sim1이 6개월간 실패 원인을
몰랐던 것이 정확히 그 상태였다.

또한 4항 전환은 항의 추가가 아니라 **교체**다. 설계식에는 `z_sov` 항이 없고 `z(d_sov)`가
있다 — sov 레벨을 sov 변화로 바꾸는 것이다. 이 역시 로그를 보고 정한다.

Phase 2(다음 거래일 이후): 로그로 3항/4항 분포와 통과율을 비교 → 계수·임계값 확정 →
진입식 교체 + `accel>0` 게이트 적용.

## 설계

### 저장 구조 — state 슬롯 2개

```
data/sim_psych_state.json
├ psych_prev_day  { date, z: {code: {z_sov, z_posters, z_hype}} }   전일 확정
└ psych_snapshot  { date, ts, z: {code: {z_sov, z_posters, z_hype}} }  직전 런
```

승격 로직이 슬롯을 2개로 줄인다. **직전 런 스냅샷의 날짜가 오늘과 다르면 그것이 곧 전일
마지막 런**이므로, 별도의 "당일 마지막" 추적이 필요 없다.

```
if snapshot.date != today:
    prev_day ← snapshot          # 승격 (하루 1회, 그날 첫 런에서)
... 파생값 계산 ...
snapshot ← 이번 런 값            # 매 런 갱신
```

날짜는 KST 기준 `%Y%m%d`. `sim_diag._today()`와 같은 방식을 쓴다.

### 파생 3항

| 값 | 정의 | 결측 시 |
|---|---|---|
| `d_sov` | z_sov(now) − z_sov(prev_day) | 0 |
| `d_hype` | z_hype(now) − z_hype(prev_day) | 0 |
| `accel` | z_posters(now) − z_posters(직전 런) | 0 |
| `accel_d1` | z_posters(now) − z_posters(prev_day) | 0 |

- **결측은 중립 0**이다. fail-closed는 매일 후보의 절반을 영구 배제하고, Sim1이 노리는
  '새로 터진 관심'을 구조적으로 못 잡는다. 반대로 '전일 최저 가정'은 후보 46%에 일괄
  보너스를 주어 임계값의 의미를 무너뜨린다. 중립 0으로 두고 `hist_missing` 플래그를
  남겨, 신규 유입군이 실제로 더 벌었는지를 한 달 뒤 로그로 판정한다.
- `prev_day`가 실제 직전 거래일이 아닐 수 있다(주말·휴장·스크래퍼 중단). `hist_days_ago`를
  기록하고 **5일 초과면 결측 취급**한다. 5일은 주말 낀 연휴(금~화)까지는 정상 이력으로
  인정하되, 그보다 오래된 값은 '전일'이라 부를 수 없다는 선이다.
- **09:30 이전에는 accel = 0**으로 둔다. 개장 30분은 z 노이즈가 90분위 2.46z로 임계값
  2.5에 맞먹어, 이 구간의 accel은 값이 아니라 잡음이다. 새로 도입하는 값이 믿을 수 없는
  구간에서 작동하지 않게 하는 것이므로 기존 진입 동작은 건드리지 않는다.
- `accel`(직전 런 기준)과 `accel_d1`(전일 기준)을 **둘 다 기록**한다. Phase 2에서 어느
  정의가 수익과 연결되는지 로그로 판정한다. 진입식에는 `accel`만 쓴다.

### z_hype

`hype_score`는 0~1 고정 스케일이지만 시간대 안정성이 검증되지 않았다. sov와 같은 처리를
적용해 횡단면 z(`z_hype`)로 저장한다. `_zmap`을 그대로 쓴다(표본 <10 또는 분산 0이면 빈
dict → 결측 처리 경로로 흡수).

### 진단 로그 확장

`sim_diag.COLUMNS`에 추가한다.

```
d_sov, d_hype, accel, accel_d1, z_hype, hist_missing, hist_days_ago, ignition4
```

`ignition4`는 설계식 4항(`1.0*z_posters + 1.0*z(d_sov) + 0.7*z(d_hype) + 0.5*z_likes`)을
**계산만 해서 나란히 기록**하는 컬럼이다. 진입 판단에는 쓰지 않는다. 현행 `ignition`(3항)과
같은 행에 남으므로, 다음 거래일 로그에서 두 지표의 분포와 통과율을 직접 비교할 수 있다.

`z(d_sov)`·`z(d_hype)`는 델타를 다시 횡단면 z화한 값이다. **이력이 있는 종목만으로 z를
계산**하고 결측 종목에는 0을 준다. 결측 종목의 0을 분포에 포함시키면 z가 왜곡된다.

컬럼 추가는 CSV 헤더를 바꾼다. `sim_diag.append`는 파일이 비었을 때만 헤더를 쓰므로, 기존
파일이 있으면 열이 어긋난다. 첫 수확 전이라 기존 파일은 아직 없지만, 있을 경우를 대비해
**헤더 불일치 시 새 파일로 회전**하는 처리를 넣는다.

## 검증

유닛테스트(`scratch/test_sim1_history.py`):

1. 날짜 롤오버 — snapshot.date != today면 prev_day로 승격, 같으면 유지
2. 같은 날 두 번째 런에서 prev_day가 덮어써지지 않음
3. 이력 결측 → d_sov=d_hype=0, `hist_missing`=1
4. `hist_days_ago` > 5 → 결측 취급
5. 09:30 이전 accel=0, 이후 정상 계산
6. `z(d_sov)` 계산 시 결측 종목이 분포에서 제외됨
7. **회귀: 기존 3항 `ignition` 값과 진입 결정이 이 변경으로 바뀌지 않음**

배포 후 다음 거래일 로그 대조:

- `hist_missing` 비율이 실측 회전율(38~48%)과 맞는가
- 그날 첫 런에서 prev_day 승격이 정확히 1회 일어났는가
- `ignition4`와 `ignition`의 분포·통과율 차이 (Phase 2 입력)
