# 심11 미너비니 — 배포 코드 재생으로 R2 수치 대조 (2026-10-02)

R2(`2026-09-29-sim11-profit-analysis.md`)의 수치는 연구 하네스(`s11bt2.py`, 벡터 연산으로 규칙을 다시 쓴 것)에서 나왔다. 이 문서는 **배포 코드 `build_watchlist_entry`·`decide_minervini`를 직접 import해 하루씩 재생하는 기준 하네스**로 같은 질문을 다시 잰다. 대상 코드는 `origin/main`과 같은 `src/strategy/simulators/sim11_minervini.py`(VCP 0.85)다.

## 결론 먼저

1. **R2 수치는 배포 동작으로 재현되지 않는다.** 배포 함수를 직접 재생하면(실적 필터는 R2처럼 '통과로 간주') VCP 0.85는 n=1380, 건당 +2.06%, 일별 t **1.55**다(R2: n=1396, +2.46%, t 2.42). VCP 0.7은 n=1136, +1.40%, t **0.88**이다(R2: 1173, +1.68%, t 1.27). 기준 하네스의 진입 집합은 R2 규칙을 배포 쪽으로 하나씩 바꿔 간 사다리의 마지막 단과 100% 같다(§1).
2. **가장 큰 차이 요인은 50일선 청산의 판정 시점이다.** R2는 종가로 판정했고, 배포는 1분 루프에서 **실시간가**가 ma50 아래로 내려가면 바로 판다. 이 하나로 t가 2.21에서 1.55로 떨어진다. 장중 ma50 청산 892건 중 54%는 그날 종가가 ma50 위로 돌아왔다. 첫 분기점은 가격 기준이다(R2는 배당까지 수정한 `Adj Close`, KIS는 배당 미수정). 이것만으로 t가 2.42에서 1.92로 떨어진다. 체계적 편향이라기보다 입력이 조금만 달라져도 결과가 크게 흔들린다는 표시다.
3. **0.7→0.85 변경은 방향으로는 맞다. 다만 R2가 댄 근거(t 2.42)는 과장돼 있다.** 기준 하네스의 모든 판(장중·종가 판정, 고정·ATR 손절, 단기·장기, 신호 단위·포트)에서 0.85가 0.7보다 낫거나 같다. 장기 포트(경로 8개 중앙값)도 연 +1.8% 대 -1.9%로 0.85가 낫다. 하지만 배포 동작에서 0.85의 단기 t는 1.55이고, 설계(1.28)·검증(0.88) 구간 둘 다 2에 못 미친다. 감시목록이 말라 거래가 0건이던 운영 문제를 푸는 변경으로는 유지할 만하다. "수익이 난다"는 근거로는 쓸 수 없다.
4. **장기(2001~, 277종목+상장폐지, 배당 미수정)에서 배포판은 알파가 없다.** 포트(300만·5슬롯·19%, 경로 8개 중앙값) 기준 연 +1.8%, MDD -85%, 같은 패널 동일가중 대비 β조정 알파 연 -6.7%다. 2010년 이후는 연 -2.2%다. 50일선 판정만 종가로 바꾸면 연 +9.1%, 알파 +0.3%(t≈0)가 된다. 이것도 시장을 이기지는 못한다.
5. **ATR×3 손절(R2 1순위)은 배포 동작에서 우선순위가 아니다.** 신호 단위로는 개선된다(단기 t 1.55→2.23, 장기 5.08→6.00). 하지만 장기 포트 알파는 그대로다(-6.7→-6.9, 상한 -15%판 -5.6). 꼬리는 깊어진다(단기 최악 -12.5→-33.4%, p1 -8.8→-24.4%, 장기 최악 -72%).
6. **권고: 손절폭보다 50일선 청산을 '종가 판정 → 다음날 시가 청산'(또는 마감 직전 판정)으로 바꾸는 쪽을 먼저 검토한다.** 사다리로 잰 이 안은 단기 t 2.54(0.85), 장기 2010~ t 3.62로 장중 판정(1.55 / 2.37)보다 낫다. 그래도 장기 포트 알파는 0 근처다. 관찰 전용을 유지하고, 실전 승격 근거로는 쓰지 않는다.

## 1. 기준 하네스(배포 코드 재생)

스크립트: scratchpad `r13_ref.py`(하네스), `r13_ladder.py`·`r13_ladder_run.py`(차이 분해), `r13_run.py`(본 실행), `r13_whip.py`·`r13_incr.py`(보조 분석).

- **EOD(e일)**: 종목마다 후보 dict를 만들어 배포 `build_watchlist_entry`에 그대로 넣는다. `price`=e일 종가, `daily_closes`=e일 **이전** 유효 종가 229개(`history_days=230`에서 오늘 행 제외), `w52_hgpr/w52_lwpr`=e일 포함 250거래일 장중 고가 최고·저가 최저(KIS 현재가 조회의 52주 고저 근사), **`eps_growth_yoy`·`revenue_growth_yoy`=100(실적 필터 '통과로 간주')** — 과거 시점 분기 실적이 없어서다. R2와 같은 조건이다.
- 유니버스 = e일 거래대금 ≥ 10억(`sim11_universe`의 유동성 필터) ∪ 보유 종목. 이력 220행 미만은 제외(`candidates_from_kis_live`의 short). 조회 순서 = 보유 → 직전 감시목록 → 나머지 코드순(`prioritize_sim11_pairs`) — 같은 날 돌파가 여럿일 때 슬롯을 누가 가져가는지가 이 순서다.
- **보유 전용 ma50 항목(PR #125)**: 보유 종목이 자격을 잃으면 `build_sim11_watchlist`와 똑같이 `{'pivot_price': None, 'ma50': ...}`를 싣는다. 이 경로가 없으면 50일선 아래로 내려간 종목의 ma50 청산이 안 걸린다.
- **장중(e+1일)**: 같은 `decide_minervini`를 일봉에서 만든 가격 스냅샷으로 여러 번 부른다(1분 루프의 근사).
  1. 시가: 시가가 손절선·ma50 아래면 시가 청산, 시가가 pivot 위면 시가 매수(갭 돌파).
  2. 하락 경로(장 시작 보유분): 저가가 손절선이나 ma50에 닿으면 **둘 중 먼저 닿는 문턱(높은 쪽)** 가격을 현재가로 넣는다 → 배포 함수가 사유(손절/50일선)와 함께 청산한다.
  3. 돌파: 고가 > pivot이면 max(시가, pivot)을 현재가로 넣는다. 거래대금 문턱은 그날 거래대금(실제 배포는 그 순간까지의 누적 — 여기가 낙관적).
  4. 진입일 청산: 손절은 진입 뒤 저가로(비관, R2와 같은 가정), 진입일 ma50은 종가로(`entryday='mixed'`, 기본). 진입일 ma50도 저가로 보는 비관판(`pess`)은 민감도로 낸다.
  5. 종가: 슬롯이 빈 뒤의 늦은 돌파 매수. `exit='close'` 모드에선 여기서 종가 < ma50 청산.
- 주문 처리는 `BaseSimulator._view/_apply/buy/sell/add_cooldown` 그대로(NAV 19%, 정수 주, 수수료 0.015%×2, 매도세 0.18%, 쿨다운 3 **달력일**). `save_state`·`log_trade`만 무력화.
- **신호 단위(signal) 모드**: `MAX_HOLDINGS`를 무한, 1건당 비중을 극소로 패치해 슬롯·자본 제약 없이 모든 신호를 센다. R2(종목별 독립 거래)와 같은 단위다. **포트 모드**는 배포 그대로(300만·5슬롯·19%).
- **ma50 청산 두 판**: `intraday`(기본 — 배포 의미: 실시간가 < 감시목록 ma50) / `close`(종가 < ma50, R2와 같은 판정 시점). 손절은 두 판 모두 장중.
- 가격: 단기는 야후 `Close/Open/High/Low`(분할만 수정 = KIS `FID_ORG_ADJ_PRC=0` 수정주가와 같은 기준), 장기는 `r8_panel.pkl`의 같은 원시 가격. 두 패널 모두 `r11_lib._clean_spikes` 적용(u11은 해당 스파이크 0건, 장기 패널은 107건).

### 하네스 검증 — 배포 재생 = 사다리 마지막 단

R2 스크립트를 그대로 옮긴 사다리(`r13_ladder.py`)의 0단이 `s11bt2.trades`와 같고, 마지막 단이 기준 하네스와 거래 단위로 같은지 확인했다.

| 비교 | VCP 0.85 | VCP 0.7 |
|---|---|---|
| 사다리 0단 vs `s11bt2` 원본 | 공통 1393 / 한쪽만 3·3, 공통분 수익률 차 0 | 공통 1172 / 1·1, 차 0 |
| 사다리 S9(종가 판정) vs 기준 하네스 `close` | 공통 1296 / 0·0 (청산일 일치 1282) | 공통 1088 / 0·0 (1077) |

- 0단의 3건 차이는 `s11bt2`의 버릇이다: **진입일에 ma50으로 청산되면 청산일을 하루 뒤로 적고(`j=i+1`) 쿨다운도 하루 더 준다.** 수익률은 같다.
- 진입 집합이 배포 재생과 100% 일치하므로, 아래 차이 분해의 각 단은 "배포 동작의 어느 부분이 R2와 다른가"를 정확히 가리킨다.

- **가장 큰 단일 요인은 ma50 청산의 판정 시점(S9→S10)이다.** 배포는 1분 루프에서 실시간가가 ma50 아래로 내려가는 순간 판다. R2는 종가로 판정했다(R2 문서 '한계'에 적혀 있던 근사). 장중으로 바꾸면 ma50 청산이 683→892건으로 늘고 건당 +11.75→+7.31로 줄어 t 2.21→1.55가 된다.

  - 같은 진입(1296건)만 놓고 보면 장중 판정이 건당 -0.64%p, 청산일이 달라진 거래가 431건이다.

- 판정: **방향은 일관되게 0.85 ≥ 0.7이다. 크기는 R2의 절반 정도이고, 배포 동작에서는 유의하지 않다(t<2).**

### 권고

- **52주 고저.** KIS `w52_hgpr/w52_lwpr`를 250거래일 장중 고가/저가로 근사했다. KIS 값의 정확한 정의와 수정주가 반영 여부는 실호출로 확인하지 않았다.
