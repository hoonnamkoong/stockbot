## 0. ★ 2026-07-21 개정 — 국면 아키텍처 정정 (사용자 방향)

6~7월 실측 백테스트(아래 §8)에서 재설계 Sim5가 -11%, Sim6가 -1%로 **여전히 손실**. 원인을
파고들며 아키텍처 오류가 드러났다.

**잘못된 접근(폐기):** "Sim5 안에 SIDEWAYS 국면 게이트를 내장" — 개별 심에 국면 판단을 넣는 것.
관심사 분리 위반. 개별 심이 국면을 스스로 판단하면 Sim10과 책임이 겹친다.

**올바른 아키텍처(사용자 확정, 이미 Sim10 메타-얼로케이터 설계와 일치):**
```
Sim0  → 시장을 3국면(BULL / SIDEWAYS / BEAR)으로 판단          [이미 구현]
Sim10 → 국면에 따라 3개 하위 알고리즘을 스위칭                  [이미 구현: program_turn.REGIME_TAG]
개별 심 → 각자 한 국면에 특화된 "순수 알고리즘" (국면판단 없음)
         BULL=Sim4-1, SIDEWAYS=Sim5, BEAR=Sim6
```
- 현재 Sim10 스위칭: `BULL→sim4_bull_daytrading, SIDEWAYS→sim5_sideways, BEAR→cash`.
  **바꿀 것은 단 하나: `BEAR→cash` → `BEAR→sim6`(인버스 ETF).**
- 개별 심 성과는 **단독이 아니라 오케스트레이션 하에서 국면별로 평가**한다. 6~7월은 BEAR라
  Sim10이 Sim5를 애초에 안 켰을 것 → Sim5 단독 -11%는 오해. Sim5는 "실제 SIDEWAYS 구간"에서만
  평가돼야 하고, 6~7월 성과의 주체는 Sim6여야 한다.

**따라서 §3~§4의 개별 게이트 논의는 폐기**하고, 아래 세 갈래로 재정의한다.

### 0.1 Sim5 = 순수 횡보 알고리즘 (게이트 없음)
- 현재 구현(레인지스윙+트레일링, §4) **유지**. 국면 게이트 내장 안 함.
- 하락장 falling-knife 문제는 Sim5가 아니라 **Sim10이 BEAR에 Sim5를 안 켬**으로 해결.
- (선택) 종목 단위 견고성: 채널이 신저점 갱신 중이면 진입 스킵 — 횡보장 안의 개별 하락종목 회피.

## 1. 문제 (근본 원인)

최근 코스피 하락·횡보 국면에서 "하락·횡보용" 두 심이 수익을 못 낸다. 라이브 상태 파일
(`db-data` 브랜치, 2026-07-21 기준)을 직접 조회해 원인을 확정했다.

### Sim6 (하락줍줍) — 6주간 매매 0건 (버그)

- `data/sim_bear_state.json`: `daily_trades: []`, `cash`가 초기값(3,000,000)과 정확히 동일.
  2026-06-11 이후 **단 한 건도 진입하지 않음**.
- 원인: `get_universe()`가 "전일 하락률 상위 30"을 `state['yesterday_decline_universe']`에
  저장했다가 다음 날 그대로 재사용한다. 이 저장값의 `change_rate`는 **캡처 당시(전일)의 값이
  박제**되어 있다 (실측 예: `CJ씨푸드1우 -29.95%`, `코오롱 -29.94%`).
- `_enrich_universe()`(trade_engine.py)는 가격·스파크라인·PER/PBR만 당일자로 갱신하고
  **`change_rate`는 절대 갱신하지 않는다**.
- 진입 조건은 `0 < daily_change <= 7.0`인데, `daily_change`가 이 박제된 큰 음수를 읽으므로
  **조건이 논리적으로 영구히 거짓** → 데드캣 반등이 실제로 일어나도 절대 못 잡는다.
- 타이밍 일치: 이 버그는 "당일→전일 하락 유니버스"로 바꾼 2026-06-11 수정에서 생겼고,
  Sim6 매매 기록도 정확히 그날부터 끊긴다.

**결론: "하락장에서 성과가 나쁜" 게 아니라 "구조적으로 절대 매수하지 않는" 상태였다.**

### Sim5 (추세눌림목) — 알파는 미세 양(+)이나 수수료가 잠식

- `data/sim_sideways_state.json`: 6/11~7/21 총 38건, 승률 39.5%, profit_factor 1.15.
- 수수료 차감 전 손익 **+16,982원(+0.57%)** 인데, 수수료 **22,928원**에 잠식되어 순 **-0.2%**.
- 회전율이 과하다(38건 / 약 30거래일 ≈ 하루 1건 이상). 근본 문제는 빈도가 아니라 **목표가가
  종목의 실제 변동폭과 무관하게 고정(+4%)** 이라는 점 — 레인지 3%짜리든 15%짜리든 똑같이
  +4%를 노려, "이겨봐야 수수료"인 셋업까지 다 잡는다.

### 사용자 방향 결정 (2026-07-21)

- Sim6: **구조 재설계** (전일 스냅샷 폐기 → 당일 실시간 스캔). staleness 버그 유형을 원천 차단.
- Sim5: "수수료를 겨우 넘기는" 수준이 아니라 **횡보장에서 수익을 극대화**하는 로직으로 재설계.
  선택 개념 = **개념 3(레인지 저점 진입 + 트레일링 청산 결합)**.

### 변경 후
```python
def get_universe(self):
    """당일 실시간 하락률 상위 30 (staleness 없음)."""
    try:
        from src.trade.kis_data_provider import KISDataProvider
        return KISDataProvider().get_fluctuation_rank(market='0001', sort='1', limit=30)
    except Exception:
        return None
```

- `run()` 말미의 `yesterday_decline_universe` 저장 로직 **삭제**.
- 진입 조건(`period_change<=-7%`, `0<daily_change<=7%`, `foreign_change>=0`, `ADX>=15`,
  우량주 필터)은 **그대로 유지** — 이제 유니버스의 `change_rate`가 당일 실측이라 정상 작동.
- 주의: `get_fluctuation_rank`가 반환하는 `change_rate`는 당일 하락률(큰 음수)이다. 진입 조건은
  `daily_change`(당일 등락)로 "반등 시작"을 보는데, 하락률 상위 종목이 장중 **양(+)으로 돌아선**
  케이스만 통과한다. 데드캣 반등의 정의와 일치.
- 판정 기준 데이터: `_enrich_universe()`가 sparkline·per/pbr·수급을 보강하므로 period_change,
  ADX는 그대로 계산 가능.

### 리스크
- 스캔 시점(장중 특정 런 시각)에 따라 하락상위 구성이 달라진다 → 신호가 시점 의존적. 다만 이는
  "전일 박제"보다 명백히 개선이며, 다른 실시간 심(Sim2/3/4)과 동일한 성질이다.
- API 콜 1회 추가(런당). 유량 부담 미미.

## 4. Sim5 재설계 (레인지 저점 진입 + 트레일링 청산)

### 4.1 개념
지수가 횡보/하락이어도 개별 종목은 순환매로 레인지 안에서 스윙한다. 이 스윙을 **종목 실제
변동폭에 비례**해 먹되, 레인지 상단을 뚫고 진짜 상승 전환하면 고정 익절로 끊지 않고 트레일링으로
계속 태운다. 즉 "횡보 구간의 스윙"과 "상승 전환 라이딩"을 하나의 규칙으로 커버.

### 4.2 로직 (안)
- **유니버스:** 현행 유지(공통 버즈 후보). 별도 스크리너 없음.
- **진입:**
  - N일 채널 산출: `channel_low = min(hist)`, `channel_high = max(hist)`,
    `channel_width_pct = (high-low)/low*100`.
  - **최소 채널폭 필터:** `channel_width_pct >= MIN_WIDTH`(초안 8%). 미달 = 스윙 여력이
    수수료 대비 무의미 → **스킵**. (이 필터가 "이겨봐야 수수료" 셋업을 원천 차단하는 핵심.)
  - 저점 근접: `현재가 <= channel_low * (1 + LOW_ZONE)`(초안 LOW_ZONE=0.03, 저점 +3% 이내).
  - 추세/반등 보강: `ADX >= 20`, `daily_change > -2.0`(당일 급락 중 진입 금지),
    체결강도 필터 유지.
  - 거래대금 하한 유지(현행 10억 → 검토: 상향 여지).
- **청산 (고정 +4% 익절 폐기):**
  - 채널 상단 접근 시 트레일링 활성화: `현재가 >= channel_high * TRAIL_ARM`(초안 0.98)이면
    트레일링 ON. 이후 고점 대비 `TRAIL_CALLBACK`(초안 2%) 하락 시 매도.
  - 상단 돌파(`현재가 > channel_high`) = 횡보 이탈 → 트레일링 유지한 채 계속 라이딩(상단 캡 없음).
  - **손절 -3% / 7일 타임스탑 유지** (손절은 항상 타이트).
- **파라미터(초안, 백테스트로 확정):** `CHANNEL_DAYS=20`, `MIN_WIDTH=8%`, `LOW_ZONE=3%`,
  `TRAIL_ARM=0.98`, `TRAIL_CALLBACK=2%`, `STOP=-3%`, `TIMEOUT=7d`, `MAX_HOLDINGS=4`.

### 4.3 ★ 데이터 제약 결정 (반드시 먼저 합의)
`CHANNEL_DAYS=20`을 라이브에서 쓰려면 20일 종가가 필요한데, 현재 sparkline은 5일치뿐이다.
파리티 원칙상 백테스트에서만 20일을 쓰고 라이브에선 5일로 도는 이중 동작은 **금지**. 세 옵션:

- **옵션 A — Naver 슬라이스 확장 (권장):** `frgn.naver` 페이지는 이미 20+행(일별 외인매매)을
  반환한다. 현재 `data_rows[:5]`를 늘리기만 하면 추가 API 없이 20일 종가 확보. **단, 공유 필드
  `sparkline_price`를 전역 확장하면 ADX/period_change를 쓰는 다른 심(Sim1/3/4/6)의 동작이
  바뀐다.** → 별도 필드 `sparkline_20d`(또는 `range_history`)를 신설해 Sim5만 소비하고,
  기존 `sparkline_price`(5일)는 그대로 둔다. 비용: enrich 파싱 1곳 + trade_engine 1곳 수정,
  API 콜 0 추가.
- **옵션 B — KIS 일봉 API 신설:** `inquire-daily-itemchartprice`(FHKST03010100) 메서드를
  `KISDataProvider`에 추가해 종목당 일봉 20개 조회. 정확하지만 종목당 1콜(유니버스 크기만큼)
  추가 → 유량·지연 부담. 옵션 A로 부족할 때만.
- **옵션 C — 채널 기간 축소(5~7일):** 데이터 확장 없이 현행 sparkline으로 짧은 채널만 사용.
  구현 최소지만 "20일 채널"의 취지(넓은 레인지 선별)가 약해짐.

**권장: 옵션 A** — 추가 콜 0, 파리티 유지, 다른 심 무영향(전용 필드). 옵션 A의 20+행 반환량이
종목별로 들쭉날쭉하면(신규 상장 등) `min(가용, 20)`으로 폴백하고 표본<10이면 진입 스킵.

  차감 후) 양전 여부.
