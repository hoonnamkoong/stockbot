# 심0(리베로) 국면 판정 재설계 — 확률 필터

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:writing-plans to create implementation plan after this spec is approved.

**Goal:** 국면 전환을 빨리·오탐 없이 잡는다. 그리고 **개선을 증명할 수 있는 구조**를 만든다 — 지금은 "개선"이 정의되지 않아 매번 다른 문제가 새로 나온다.

**Architecture:** 10분 해상도 관측 이력 + 사후 양방향 평활 라벨러 + 순수 판정기 + 재생 가능한 평가 하네스. 판정기는 Δt를 아는 3상태 베이즈 필터로, 비대칭 결정 임계를 갖는다.

**Tech Stack:** Python 3.12, pytest. 새 의존성 없음(numpy/scipy 불필요 — 3×3 행렬과 정규 우도는 표준 라이브러리로 충분하다).

## Global Constraints

- `current_regime` 계약 불변: `"BULL"|"SIDEWAYS"|"BEAR"` 문자열. **Sim6·Sim10·Sim7 수정 금지.**
- `calc_bull_score` 계산식 **변경 금지** — Sim7의 `bull_score >= 45` 게이트가 읽는다.
- 판정기는 **순수 함수**다. 파일·전역 상태·시계에 접근하지 않는다. (지금 불가능한 사전 검증을 가능하게 하는 유일한 조건)
- 가짜 값 금지: 조회 실패·필드 부재는 생략하거나 약한 증거로 처리하고, 0/50으로 지어내지 않는다.
- 룩어헤드 금지: 판정기는 과거 관측만 본다. 미래를 쓰는 것은 **라벨러뿐**이다.
- 매매 집행·주문 경로·예산 로직 일절 무관.

## 1. 현재 문제 — 버그가 아니라 구조

### 1.1 채점되는 "예측"에 모델이 없다

`finalize_eod`가 `calibration_log`에 넣는 값은 그날 **첫** EOD 예측이다. 09:00에는 측정값이
1개뿐이라 `velocity = 0`이 되고, 예측식이 붕괴한다.

```
pred = last + velocity × hours_left × EOD_DAMPING
     = last + 0
     = 09:00 실측 breadth
```

실측 확인(2026-07-30): 09:00 breadth 51.0 → EOD 예측 51.0. **동일.**

즉 차트에 보이는 "예측 갭"은 모델 오차가 아니라 **아침에서 종가까지 시장이 뒤집힌 폭**이다.

| 날짜 | 09:00 | EOD | 갭 |
|---|---|---|---|
| 07-21 | 12 | 70 | -58 |
| 07-29 | 67 | 11 | +56 |
| 07-22 | 98 | 71 | +27 |

### 1.2 속도 외삽이 무모델 기준선보다 나쁘다

같은 날의 EOD 예측을 생성 시각별로 분리(14일, 98건):

| 생성 시각 | MAE | 편향 |
|---|---|---|
| 09:00 (외삽 없음) | 17.6p | +5.2p |
| **10:00** | **28.3p** | **+24.0p** |
| 11:00 | 20.9p | -10.0p |
| 12:00 | 13.0p | +0.6p |
| 15:00 | 2.3p | -1.0p |

1시간 속도 하나를 `hours_left = 5.5`에 곱하는 구조다. 아침 개장 갭 되돌림이 종일 이어진다고
가정해 +24p를 과대추정한다. **기준선과 비교하지 않았기 때문에 이것이 드러나지 않았다.**

### 1.3 예측을 아무도 읽지 않는다

`intraday.predictions`를 읽는 코드는 없다. `trade_engine`이 기록만 한다.
돈을 움직이는 것은 `classify_regime`(그 시점 실측)에 5런 최빈값 평활을 씌운 값이다.

| 소비자 | 읽는 값 | 결과 |
|---|---|---|
| Sim6 | `current_regime == BEAR` | 인버스 ETF 매수 |
| Sim10 | `current_regime` | 유니버스·하위전략 전환 |
| Sim7 | `bull_score >= 45` | 강력매수 집행 |

**즉 지금까지 채점해온 "예측 성능"은 매매와 연결되지 않은 별도 지표였다.**

(2026-07-30 기준 실계좌 프로그램은 Sim4-1로 세팅돼 있고 `sim4_bull_daytrading.py`는 국면을
참조하지 않는다. 그래서 국면 판정 변경이 지금은 실계좌에 영향이 없다. **프로그램을 Sim10으로
바꾸는 순간 라이브가 된다** — 그때는 이 문서의 승격 게이트가 실계좌 게이트가 된다.)

### 1.4 10분 관측의 5/6을 버리고 있다

```python
@staticmethod
def _hour_label(now):
    return now.strftime('%H:00')      # 09:10, 09:20 … 전부 '09:00'
```

같은 라벨이면 첫 값만 남긴다(`if not any(m['t'] == label for m in meas)`). 10분마다 도는데
시간당 1건만 기록된다. 게다가 `intraday`는 날짜가 바뀌면 리셋되고, 백필은 KIS **당일**분봉이다.

**결과: 10분 지평 모델을 학습·검증할 이력이 현재 0이다.**

### 1.5 평활이 전환을 늦추는 것이 설계다

`_confirm_regime`은 최근 **5런** 최빈값을 쓰고 과반(3)을 요구한다.

- 10분 간격이면 전환 확정에 최소 **30분** 지연
- 런 간격이 불규칙하면(Tasker 발화) "5런"이 뜻하는 시간이 매일 다르다 →
  **라벨이 시장이 아니라 폰이 언제 울렸는지에 의존한다**
- 07-29 사례: `daily_regime_log`에 `regime=BEAR`인데 `breadth=67`. AND 게이트로는
  SIDEWAYS가 나와야 하는데 전날들의 BEAR가 최빈값으로 끌려왔다

### 1.6 AND 게이트는 전환기에 구조적으로 안 켜진다

```python
if breadth >= 60 and momentum >= 2.0 and trend >= 20:  return "BULL"
if breadth <= 40 and momentum <= -2.0 and trend >= 15: return "BEAR"
```

- 전환 초기에는 momentum이 아직 따라오지 않아 세 조건이 동시에 성립하지 않는다
- `trend`는 `_top100_trend_from_csv()`로 **일봉 CSV**에서 만든다 → **장중에 변하지 않는 상수**
- ADX 근사는 |변동|의 평균이라 **방향이 없다.** 상승·하락 조건 양쪽에 같은 부호(`>=`)로
  들어가 있는 것이 그 증거다. 실질적으로 "시장이 움직인다" 필터일 뿐이다

### 1.7 정답이 순환한다

breadth를 60/40으로 잘라 국면을 만들고, 그 국면의 적중을 다시 breadth로 채점한다.
경제적 의미가 어디에도 없고, "적중률"이 같은 양을 두 시각에 계산한 것의 일치율이다.

### 1.8 아침 국면은 종가 국면과 59%만 일치한다 — 그리고 비대칭이다

top100 99거래일 실측(시가 대비 전일종가 → 종가 대비 전일종가):

| 전환 | 일수 |
|---|---|
| 아침 SIDEWAYS → 종가 BEAR | 11 |
| 아침 BULL → 종가 BEAR | **10** |
| 아침 BULL → 종가 SIDEWAYS | 10 |
| 아침 BEAR → 종가 SIDEWAYS | 6 |
| 아침 SIDEWAYS → 종가 BULL | 3 |
| **아침 BEAR → 종가 BULL** | **1** |

**07-29형(낙관 → 붕괴)이 10일, 07-21형(비관 → 반등)이 1일이다.** 상시 위험은
아침 낙관을 그대로 믿는 쪽이고, 이 비대칭은 현재 코드에 전혀 반영돼 있지 않다.

참고: 아침 breadth 구간별 종가 평균 — `60~80` 구간이 **43.2**로 내려온다(강세가 유지되지 않는다).

## 2. 목표와 성공 기준

### 2.1 무엇을 예측하는가

**다음 관측 시점(≈10분 뒤)의 거시 국면**, 특히 **전환 시점**. 일 단위 정확도는 부수적 목표다.

리베로의 유일한 용도는 자본 배분(Sim10의 하위 전략 선택, Sim6의 게이트)이다.
개별 종목 판단이 아니라 거시 장 상태를 잡는다.

### 2.2 손실 함수

breadth MAE가 아니다. **전환 탐지 지연 + 오탐**, 그리고 §1.8의 비대칭을 반영한 비용이다.

```
cost = w_late_exit  × (BEAR 전환 지연 분 / 60)
     + w_late_entry × (BULL 전환 지연 분 / 60)
     + w_false      × (오탐 횟수)
     + w_miss       × (끝까지 못 잡은 전환 횟수)
     w_late_exit > w_late_entry     ← §1.8 실측 근거(10일 vs 1일)
```

`w_miss`가 없으면 **`always_sideways`가 비용 0으로 1등이 된다** — 전환을 전부 놓치는데
지연도 오탐도 0이기 때문이다. 못 잡은 전환에 값을 매겨야 표가 의미를 갖는다.
지연을 60으로 나누는 것은 분과 횟수의 환산율이다(1시간 지연 = 1회 오탐).

가중치는 명시 상수로 코드에 두고 근거를 주석에 남긴다. 그리고 `cost` 하나만 내보내지
않고 구성요소를 따로 내보낸다 — 가중치가 숫자를 숨기지 못하게 한다.

### 2.3 승격 게이트

확률 필터는 **기준선 4개 전부를 상대로** 비용이 개선되고 **오탐이 늘지 않을 때만** 승격한다.
하나만 좋아지면 승격하지 않는다.

기준선: ① 항상 SIDEWAYS ② 즉시 반응(평활 없음) ③ 현행(5런 최빈값+AND게이트) ④ 히스테리시스

④가 중요하다 — 확률 필터가 히스테리시스를 못 이기면 복잡도를 정당화할 수 없다.

## 3. 아키텍처

```
[관측]  10분마다 (breadth, momentum, trend, sample)
   │            ↑ breadth = 등락률>0 비율(폭), momentum = 등락률 중앙값(방향·강도)
   │              둘 다 네이버 시총 4페이지 한 번에서 나온다 — 추가 수집 비용 0
   ▼ 저장
[이력]  data/regime_observations.csv  (append-only, 롤링 60거래일)
   │
   ├─▼ 사후(미래 포함) ────────────────┐
   │  [라벨러] 양방향 평활 → 국면 라벨 + 전환 시각
   │                                    │
   ▼ 과거만                             ▼
[판정기](순수) ─────────────►  [평가 하네스] 지연·오탐·비대칭비용 + 캘리브레이션
   │                                  △ 기준선 4개와 항상 비교
   ▼
current_regime (계약 유지) · bull_score (불변) · regime_prob (신규) · regime_since (신규)
```

### 3.1 왜 이 구조인가

지금 판정은 `run()` 안에서 상태를 읽고 쓰며 일어난다. 그래서 **과거 데이터로 재생할 수 없고**,
어떤 변경도 사전 검증이 불가능했다. **이것이 "매번 새 문제가 튀어나온다"의 뿌리다.**

판정기를 `(prev_state, obs, params) -> decision` 순수 함수로 분리하는 것 하나가
하네스 재생을 가능하게 한다.

## 4. 구성요소

### 4.1 관측 이력 — `data/regime_observations.csv`

| 열 | 뜻 |
|---|---|
| `ts_kst` | `YYYY-MM-DD HH:MM` — **분까지.** `_hour_label` 폐기 |
| `breadth` | top100 등락률>0 비율 (%) |
| `momentum` | top100 등락률 중앙값 (%) |
| `trend` | 일봉 ADX 근사 median (장중 상수임을 알고 기록) |
| `sample` | 표본 종목수 |
| `source` | `top100_live` \| `candidates` |

- append-only. db-data 브랜치에 커밋(이 레포의 DB가 파일이고, append가 병합에 강하다)
- 롤링 60거래일 ≈ 2,340행. state JSON에 넣으면 매 런 전체 재작성이라 계속 커진다
- **표본 80 미만도 기록한다.** 지금은 버리지만(`return None`), 확률 모형에서는 약한 증거다

### 4.2 라벨러 — `src/strategy/regime_label.py` (순수)

```python
def label_regimes(observations, window, quantiles) -> list[RegimeLabel]
def transitions(labels) -> list[Transition]     # (ts, from_regime, to_regime)
```

- `breadth`·`momentum` 각각에 **중심 대칭 이동중앙값**(창 `window`) 적용 → 2차원 평활값
- 대칭 평활은 미래를 쓴다. **정답 쪽만** 쓰므로 룩어헤드가 아니라 정보 비대칭의 정상적 형태다
- 2차원 → 3상태 사상 규칙(시작값, 하네스로 재검토):

  ```
  b_hi = breadth의 q_hi 분위수,  b_lo = q_lo 분위수     (강도도 동일하게 m_hi, m_lo)
  BULL      : 평활 breadth >= b_hi  AND  평활 momentum >= m_hi
  BEAR      : 평활 breadth <= b_lo  AND  평활 momentum <= m_lo
  SIDEWAYS  : 그 외
  ```

  라벨러에서 AND를 쓰는 것은 판정기와 다른 문제다 — 라벨은 **양쪽이 확실히 동의하는 구간만**
  국면으로 부르는 것이 낫다(애매한 구간이 SIDEWAYS로 가야 지연 측정이 깨끗해진다).
  판정기 쪽 AND 게이트가 문제였던 이유는 실시간에 미래를 못 봐서다(§1.6).

- **분위수 창**: 전체 표본이 아니라 **직전 60거래일 롤링**. 전체를 쓰면 미래가 과거 라벨에
  스며들고(라벨은 미래를 써도 되지만 *일관성*을 위해 창을 고정한다), 시장 레짐 이동을 못 따라간다.
  `q_hi = 0.67`, `q_lo = 0.33`을 시작값으로 두고 스윕한다
  - 고정 60/40을 쓰지 않는 근거: 실측 종가 breadth 평균이 48.5여서 60/40 컷은 SIDEWAYS를
    과도하게 넓힌다. 시장 레짐이 변하면 고정 컷의 의미도 변한다
- `window`는 스윕해서 **라벨 전환 횟수의 안정성**으로 고른다(너무 짧으면 잡음이 전환이 되고,
  너무 길면 진짜 전환이 지워진다)

### 4.3 판정기 — `src/strategy/regime_filter.py` (순수)

```python
def filter_step(prev, obs, params) -> RegimeDecision
#   prev   : {probs: {BULL,SIDEWAYS,BEAR}, regime, since_ts, last_ts}
#   obs    : {ts, breadth, momentum, sample}
#   params : {mu, sigma, tau_dwell, tau_bull, tau_bear}
#   반환   : {probs, regime, since_ts, reason}
```

**① 예측** — `p̄ = A(Δt)ᵀ · p_prev`

`A(Δt)`의 자기전이확률 `a = exp(-Δt / tau_dwell)`, 나머지 확률은 다른 두 상태에 분배.
`Δt = obs.ts - prev.last_ts` (분).

> 불규칙 런 간격이 여기서 정직하게 처리된다. 30분 만에 온 관측은 10분 관측보다
> 사전확률이 더 평탄해진다. 현행 "최근 5런"이 못 하는 일이다.

**② 갱신** — `p ∝ p̄ ⊙ L(obs)`

```
L_s = N(breadth; mu[s].b, sigma_eff[s].b) × N(momentum; mu[s].m, sigma_eff[s].m)
sigma_eff = sigma × sqrt(100 / max(sample, 1))     # 표본이 적으면 덜 믿는다
```

축 독립 가정은 단순화다. 스펙에 명시하고, 하네스가 이 단순화의 대가를 측정한다.

**③ 결정** — 비대칭 임계

```
if p[BEAR] > tau_bear:  regime = BEAR      # 낮게 — 늦게 나가면 손실
elif p[BULL] > tau_bull: regime = BULL     # 높게 — 늦게 들어가면 기회손실(더 싸다)
else: regime = SIDEWAYS
```

**관성은 전이행렬이 담당하므로 별도 평활을 두지 않는다.** `_confirm_regime` 폐기.

**④ `trend`는 판정에서 제외한다.** 장중 상수이고 방향이 없다(§1.6).
남기더라도 게이트가 아니라 신뢰도 감쇠로만 쓴다 — 이번 범위에서는 쓰지 않는다.

### 4.4 파라미터 출처

| 파라미터 | 출처 |
|---|---|
| `mu[s], sigma[s]` | **99일 일봉으로 부트스트랩.** `output/ohlcv_top100.csv`로 일별 (폭, 강도) 계산 → 라벨러로 라벨 → 국면별 평균·표준편차. 일 단위지만 같은 지표·같은 유니버스라 분포의 위치와 폭은 10분에도 근사 유효 |
| `tau_dwell` | 하네스 스윕 |
| `tau_bull, tau_bear` | 하네스 스윕 (비대칭 유지) |

**이것이 "이력 0" 벽을 우회하는 방법이다.** 관측모형은 이미 있는 99일로 시작하고,
결정 파라미터만 10분 이력이 쌓이는 대로 재스윕한다.

### 4.5 평가 하네스 — `src/strategy/regime_eval.py` (순수)

```python
def replay(observations, decider, params) -> list[RegimeDecision]
def score(decisions, labels, weights) -> EvalResult
def calibration(decisions, labels) -> {brier, reliability_bins}
```

출력:
- 전환 탐지 지연 (중앙값·분포), 오탐 수, 미탐 수, §2.2 비대칭 비용
- **캘리브레이션**: Brier score + reliability curve.
  "P(BEAR)=0.7이라 말한 시점들 중 실제로 70%가 BEAR였나". 점 추정만 내보내면
  과신을 감지할 방법이 없다 — 현 구조에 없는 축이다
- **기준선 4개를 항상 같은 표에 출력한다.** 기준선 없이 개선을 주장하지 않는다

## 5. 단계

### 단계 0 — 측정 가능하게 만들기 (선행 필수)

1. `regime_observations.csv` 기록 (`_hour_label` 폐기, 분 단위)
2. 라벨러 + 하네스 + 기준선 4개
3. 99일 일봉으로 관측모형 부트스트랩
4. **(확인 필요)** KIS 과거 일자 분봉으로 10분 breadth 소급 재구성이 가능한가.
   현재 `_backfill_breadth_kis`는 당일분봉만 쓴다. 가능하면 단계 1을 몇 주 앞당긴다.
   **되면 좋고 안 되면 기다린다** — 계획을 이 가능성에 의존시키지 않는다

### 단계 1 — 확률 필터

1. `filter_step` 구현 + 단위 테스트
2. **일 해상도 1차 비교**: 99일 일봉을 관측 시계열로 보고 하네스를 돌린다. `tau_*`를 스윕해
   기준선 4개와 비교한다. 10분 이력을 기다리지 않고 **여기서 설계의 사활이 갈린다** —
   일 해상도에서 기준선을 못 이기면 10분에서도 못 이길 가능성이 높고, 그때는 되돌아온다
3. `regime_shadow`로 병기 기록 배선(계약 무변경). 병기 기록이 곧 A/B 기간이다

**구현 계획의 완료 조건은 여기까지다** — 2번의 비교표가 나오고 3번이 배포되면 끝이다.
`current_regime` 승격은 10분 이력이 쌓인 뒤의 별건이고, §2.3 게이트로 판단한다.

### 단계 2 — 승격 (별건, 이력 축적 후)

10분 이력으로 `tau_*` 재스윕 → §2.3 게이트 통과 시 `current_regime` 배선.
축적 기간의 병기 기록이 그대로 검증 데이터가 된다.

## 6. 테스트

전부 순수 함수라 pytest로 덮는다.

| 대상 | 무엇을 지키나 |
|---|---|
| `parse/append` 이력 | 같은 분에 두 번 돌면 한 행(멱등). 표본 80 미만도 기록된다 |
| 라벨러 | 대칭 평활이 미래를 쓴다(의도). 분위수 임계가 분포 이동에 따라간다. 창이 짧으면 전환이 늘고 길면 줄어든다 |
| `filter_step` | Δt가 크면 사전확률이 평탄해진다. 표본이 적으면 우도가 약해진다. 비대칭 임계가 BEAR를 먼저 켠다. 확률 합이 1이다 |
| 부트스트랩 | 99일에서 국면별 μ·σ가 나오고, 국면 간 μ 순서가 BULL>SIDEWAYS>BEAR다 |
| 하네스 | 완벽한 판정기의 지연이 0이다. 항상-SIDEWAYS의 미탐이 전체 전환 수와 같다 |
| 계약 | `current_regime`이 세 문자열 중 하나다. `bull_score` 계산식이 안 바뀌었다 |

## 7. 하지 않는 것

- **지도학습 분류기** — 이력이 0이고, 쌓여도 하루 39슬롯이라 검증 가능한 표본까지 수 개월이다.
  표본이 얇은데 자유도가 크면 과적합만 남는다. 단계 1의 하네스가 갖춰진 뒤 재검토한다
- **`bull_score` 재정의** — Sim7의 게이트가 읽는다. 건드리면 매매가 바뀐다
- **Sim6·Sim10 수정** — `current_regime` 문자열 계약을 유지하므로 불필요
- **EOD breadth 예측 개선** — 아무도 읽지 않는다(§1.3). 나우캐스트 채점은 표시용으로 남기되
  이 문서의 목표가 아니다
- **`trend` 살리기** — 장중 상수 + 방향 없음. 방향 있는 추세 지표가 필요하면 별건이다
